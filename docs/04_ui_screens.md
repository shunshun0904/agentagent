# 画面設計

最終更新: 2026-10-09

## 1. 画面一覧

| パス | 画面 | 目的 |
| --- | --- | --- |
| /login | ログイン | Google でログイン(Gmail 連携)。開発時はデモユーザーでログイン |
| / | ダッシュボード | 承認待ち、送信予定、未処理、案件数などの概況と、対応が必要なスレッド |
| /inbox | 受信箱 | 全エージェントとのスレッド一覧。ステータス、エージェント、分類、件名で絞り込み |
| /inbox/[threadId] | スレッド詳細 | メールの履歴、AI の分析、返信案の確認と操作、手動返信 |
| /approvals | 承認キュー | 承認待ち・送信予定・失敗・送信済み・却下の返信案をタブで表示し、編集・承認・却下・即時送信 |
| /opportunities | 案件パイプライン | 案件をステージ別のボードで表示。セレクトでステージを変更 |
| /opportunities/[id] | 案件詳細 | 案件情報の編集、AI の適合評価、紐づくスレッド |
| /agents | エージェント一覧 | 会社ごとの状態、担当者数、スレッド数、案件数、評価 |
| /agents/new | エージェント登録 | 手動登録(ドメインを登録すると AI 判定なしで取り込み) |
| /agents/[id] | エージェント詳細 | 設定(状態、自動返信、常に承認、メモ)、担当者の編集、スレッドと案件 |
| /settings | 設定 | Gmail 連携、AI の設定表示、プロフィール、返信ポリシー |
| /activity | 活動ログ | AI の判定、送信、同期、設定変更の記録。種類で絞り込み |
| /privacy | プライバシーポリシー | 扱う情報と外部サービスへの提供範囲。ログインなしで表示(OAuth 同意画面に URL を登録する) |
| /terms | 利用規約 | 利用条件。ログインなしで表示(OAuth 同意画面に URL を登録する) |

共通レイアウト: 左にナビゲーション(受信箱と承認キューには件数バッジ)、「今すぐ同期」ボタン、Gmail 連携状態、ログアウト。スマートフォン(画面幅 768px 未満)では、上部バーの「メニュー」から同じ内容を開く。表の画面(エージェント一覧)はカード表示に、活動ログは日時と本文を縦に並べる。

## 2. 主要画面の構成

### 2.1 ダッシュボード

- 統計タイル: 承認待ち、送信予定、24時間の送信、未処理メール(エラー件数を併記)、進行中の案件、有効なエージェント
- Gmail 未連携、API キー未設定の警告
- 対応が必要なスレッド(要対応と対応中の新しい順)
- 送信予定の返信(予定時刻順)
- 今後の面談(案件の面談日時)
- 最近の活動

### 2.2 スレッド詳細

- ヘッダー: 件名、エージェント(リンク)、担当者、分類バッジ、ステータスバッジ。ステータス変更のセレクト(変更即保存)、自動返信の停止/再開
- メール一覧(古い順): 受信と送信で背景色を分ける。受信メールには分類、確信度、AI の要約。未処理は「分析待ち」、失敗は「再処理」ボタン
- 返信案一覧(新しい順): `ReplyCard`
- 自分で返信を書く: テキストエリア。「今すぐ送信」と「営業時間内に予約送信」
- 右カラム: スレッドの要約、相手の質問、候補日時、回答期限、エージェント情報(メモ、設定)、紐づく案件

### 2.3 返信案カード(`ReplyCard`)

- 状態バッジ(承認待ち、送信予定、送信済みなど)、判定(自動返信、承認制、手動)、確信度、本人編集の有無、作成・送信予定・送信時刻
- 判定理由、返信に含まれる内容(コミットメント)、確認ポイント、送信失敗時のエラー
- AI の判断理由(折りたたみ)、モデルとプロンプトのバージョン
- 本文: 承認待ち・失敗・却下・取消は編集可能なテキストエリア。送信予定・送信済みは読み取り専用
- 操作
  - 承認待ちなど: 承認して送信予約、今すぐ送信、下書きを保存、却下
  - 送信予定: 今すぐ送信、送信を取り消す

### 2.4 承認キュー

- タブ: 承認待ち、送信予定、失敗、送信済み、却下・取消(件数付き)
- 各返信案の上に、スレッド件名(リンク)、分類、エージェントと担当者、返信先メール(折りたたみで本文表示)

### 2.5 案件パイプライン

- 進行中のステージ(新規、検討中、応募済、面談調整中、面談済、オファー)を横並びの列で表示
- カード: 案件名(リンク)、エージェント、単価、適合度バッジ、リモート可否、ステージ変更のセレクト
- 終了した案件(契約、辞退、見送り、終了)は下にリスト表示

### 2.6 設定

- Gmail 連携: 連携アカウント、最終同期、エラー、再連携と解除
- AI: API キーの設定有無、モデル、effort(環境変数の表示のみ)
- プロフィール: AI が参照する本人情報のフォーム
- 返信ポリシー: 運用モード、承認カテゴリ、返信しないカテゴリ、承認コミットメント、新規エージェントの初回承認、信頼度閾値、自動返信上限、タイムゾーン、営業時間、週末送信、送信遅延、全員に返信、AI への追加指示

## 3. 操作とサーバーアクションの対応

| 操作 | サーバーアクション | 結果 |
| --- | --- | --- |
| 返信案の保存・承認・即時送信・却下・取消 | `replyFormAction` | Reply の状態更新、必要なら Gmail 送信 |
| スレッドのステータス変更、ミュート | `threadStatusAction`, `threadMuteAction` | Thread の更新 |
| 手動返信 | `manualReplyAction` | Reply(MANUAL)を作成し送信または予約 |
| 失敗メールの再処理 | `reprocessMessageAction` | Message を PENDING に戻して処理を実行 |
| 案件のステージ変更、編集 | `opportunityStageAction`, `updateOpportunityAction` | Opportunity の更新 |
| エージェントの登録・編集、担当者の編集 | `createAgentAction`, `updateAgentAction`, `updateContactAction` | Agent / Contact の更新 |
| プロフィール、返信ポリシーの保存、Gmail 連携解除 | `saveProfileAction`, `savePolicyAction`, `disconnectGoogleAction` | 設定の更新 |
| 今すぐ同期 | `syncNowAction` | 同期 → 処理 → 送信を実行し活動ログへ |

## 4. 表示規則

- 日時は `Asia/Tokyo` で `YYYY/MM/DD HH:MM`。一覧では相対表記(「3分前」など)
- 分類バッジの色: 案件紹介は藍、日程系は琥珀、単価・契約は赤、一斉配信などは灰
- 返信案の状態: 承認待ちは琥珀、送信予定は藍、送信済みは緑、失敗は赤
- 適合度バッジ: 80 以上は緑、60 以上は琥珀、それ未満は灰
