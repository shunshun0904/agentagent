# エージェントエージェント 要件定義

最終更新: 2026-10-09

## 1. 背景と目的

フリーランスエンジニアは複数のフリーランスエージェント(案件紹介会社。以下「エージェント」)に登録し、各社の営業担当者から案件紹介・状況確認・面談調整・契約手続きの連絡を受ける。連絡は会社ごとに個別に届き、返信の遅れは案件機会の損失やエージェントとの関係悪化につながる。

「エージェントエージェント」は、エージェントとのメールのやり取りをAIが本人に代わって行い、全エージェントとのやり取りを一つの画面で一元管理するサービスである。相手の営業担当者には本人が返信しているように見える。AIによる返信であることはメール上で明示しない。

## 2. 用語

| 用語 | 意味 |
| --- | --- |
| ユーザー | 本サービスを利用するフリーランスエンジニア |
| エージェント | フリーランス向けの案件紹介会社 |
| 担当者 | エージェント側の営業担当者(メールの送信者) |
| スレッド | Gmailのスレッド単位のやり取り |
| 案件 | エージェントから紹介されたプロジェクト |
| 返信案 | AIが生成した返信メール。自動送信されるか、承認待ちになる |
| ポリシー | 自動返信の可否や送信タイミングを決める設定 |

## 3. スコープ

### 3.1 MVP(本リポジトリで実装)

- Google OAuthによるログインとGmail連携
- 受信メールの定期取り込みと、エージェントからのメールの判別
- AIによる分類(12カテゴリ)、要約、案件情報の抽出
- AIによる返信文の生成(本人のプロフィール、文体、方針に基づく)
- 運用モード「自動返信 + 重要案件のみ承認」。設定で「全件承認」「完全自動」に切替可能
- 人間らしい送信タイミング(営業時間内、ランダム遅延)
- 一元管理ダッシュボード(受信箱、承認キュー、案件パイプライン、エージェント一覧、設定、活動ログ)

### 3.2 対象外(将来の拡張候補)

- Chatwork、Slack、LINEなどメール以外のチャネル
- 複数ユーザー(チーム)利用
- カレンダー連携による面談枠の自動確定
- スキルシートの自動生成と添付
- 電話対応

## 4. 主要ユースケース

| ID | 状況 | システムの動作 |
| --- | --- | --- |
| UC1 | 新規エージェントから登録お礼・挨拶メールが届く | エージェントと担当者を自動登録し、お礼と希望条件を伝える返信案を作成する。新規エージェントへの初回返信は承認待ちにする |
| UC2 | 案件紹介メールが届く | 案件情報を抽出して案件として登録する。希望条件に合えば興味を示し不足情報を質問する返信を自動送信する。明らかに合わない場合は辞退案を承認待ちにする |
| UC3 | 稼働状況や希望条件の確認メールが届く | プロフィールの内容に基づいて自動返信する |
| UC4 | 面談の日程調整メールが届く | 候補日の提示はポリシーで設定した可用性に基づき自動返信する。日時の確定は承認待ちにする |
| UC5 | 単価交渉や契約手続きのメールが届く | 返信案を作成し、必ず承認待ちにする |
| UC6 | 一斉配信や案件一覧のメルマガが届く | 返信しない。ログにのみ記録する |
| UC7 | ユーザーが承認キューを開く | 返信案を編集、承認、却下、即時送信できる |
| UC8 | ユーザーが案件やエージェントを管理する | 案件のステージを更新し、エージェントを一時停止やブロックできる |
| UC9 | ユーザーがGmailから手動で返信する | 送信済みメールを取り込み、スレッドの履歴に反映する。同じメールに二重返信しない |

## 5. 機能要件

| ID | 要件 |
| --- | --- |
| F-01 | Google OAuth(Gmailスコープ付き)でログインする。`ALLOWED_GOOGLE_EMAILS` に列挙したメールアドレスのみログインを許可する |
| F-02 | Gmailを定期的にポーリングし、新着メールを取り込む。既知のエージェントのドメインからのメールは無条件に取り込み、未知の送信者はAIが「フリーランスエージェントか」を判定する |
| F-03 | 送信者ごとの判定結果を保存し、同じ送信者を繰り返しAIに判定させない |
| F-04 | 受信メールを12カテゴリに分類し、信頼度(0から1)を付ける |
| F-05 | 案件情報(案件名、単価、期間、勤務地、リモート可否、必要スキル、開始時期)、提示された候補日、質問事項を抽出する |
| F-06 | 返信文は日本語のビジネスメールとして生成する。宛名、挨拶、本文、結び、署名を含む |
| F-07 | 返信文にはプロフィールに無い事実を書かない。返信が含むコミットメント(辞退、日程確定、単価提示、条件合意、資料送付、興味表明、候補日提示)を構造化して出力する |
| F-08 | ポリシー、分類、コミットメント、信頼度、エージェントの状態に基づき、`auto_send`、`needs_approval`、`no_reply` のいずれかを判定する |
| F-09 | 返信はGmail APIで元のスレッドに送る。`In-Reply-To` と `References` ヘッダーを設定する |
| F-10 | 送信時刻は営業時間内かつランダム遅延後とする。営業時間外に生成した返信は翌営業日の開始時刻以降に送る |
| F-11 | 承認キューで返信案の編集、承認、却下、即時送信ができる |
| F-12 | 案件のステージを管理する(新規、検討中、応募済、面談調整中、面談済、オファー、契約、辞退、見送り、終了) |
| F-13 | エージェントごとに担当者、ステータス(有効、一時停止、ブロック)、メモ、個別ルール(自動返信の無効化など)を持つ |
| F-14 | すべてのAI判定、送信、ユーザー操作を活動ログに記録する |
| F-15 | 設定画面でプロフィール、返信ポリシー、Gmail連携、AI設定を変更できる |
| F-16 | 同期は「今すぐ同期」ボタン、cronエンドポイント、ワーカープロセスのいずれからでも実行できる |

## 6. 非機能要件

| 分類 | 要件 |
| --- | --- |
| セキュリティ | OAuthのリフレッシュトークンはAES-256-GCMで暗号化して保存する。cronエンドポイントは `CRON_SECRET` による認証を必須にする。セッションはHTTP only Cookieで管理する |
| 安全装置 | 自動返信のループを防ぐため、スレッドごとの1日あたり自動返信数に上限を設ける。自動応答メール(不在通知など)には返信しない。信頼度が閾値未満の返信は承認待ちにする。AIが人間の確認を要すると判断した返信は承認待ちにする |
| コスト | 受信メール1通あたりLLM呼び出しは最大2回(分析と返信生成)。未知の送信者の判定は送信者ごとに1回 |
| 可観測性 | LLMのモデル名、トークン使用量、判定理由を返信案に保存する |
| 性能 | ポーリング間隔は環境変数で設定する(既定5分)。1回の同期で取り込むメール数に上限を設ける |
| 可搬性 | PostgreSQLが動く環境ならどこでも動作する。Vercelなどのサーバーレス環境ではcronエンドポイントを使う |

## 7. 受け入れ基準(MVP)

1. Googleアカウントでログインし、Gmail連携が完了する
2. 同期を実行すると、エージェントからのメールがスレッドとして受信箱に表示される
3. 案件紹介メールから案件が自動登録され、案件パイプラインに表示される
4. ポリシーに従い、自動返信対象の返信案は予定時刻に送信され、承認対象は承認キューに表示される
5. 承認キューで編集、承認したメールがGmail上で元のスレッドへの返信として送信される
6. 単価交渉、契約、面談確定のメールへの返信は自動送信されない
7. 活動ログにAIの判定と送信の記録が残る
